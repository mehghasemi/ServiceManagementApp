# نسخه محلی 0.1.0-preview.1

## هدف و محدوده واقعی

تجربه گردش‌کار با داده ساختگی پیش از تصمیم‌های بعدی. سه صفحه کارهای امروز، برنامه‌های مشتریان و نیازمند تصمیم کار می‌کنند. ایجاد/ویرایش برنامه، ثبت نتیجه پیگیری، جست‌وجو، فیلتر، مرتب‌سازی، صفحه‌بندی و مشاهده تاریخچه پیاده‌سازی شده‌اند.

پایگاه داده این مرحله SQLite محلی است؛ جایگزین معماری هدف PostgreSQL نیست. دیتابیس روی شبکه به اشتراک گذاشته نمی‌شود. برنامه فقط loopback را می‌پذیرد. همه کاربران محیط نمایشی با ورود صریح به یک هویت نمونه وارد می‌شوند؛ سه نقش سازمانی هنوز وجود ندارند. scope ایجادکننده روی مسیرهای خواندن و نوشتن اعمال می‌شود، اما مدل تیمی نیست.

## ساختار

- config: تنظیمات، middlewareهای Django و مسیرها.
- planning/models.py و migrations: برنامه، کیس نمونه، پیگیری، audit و کلید عملیات تکراری.
- planning/forms.py: ورودی‌ها، اعتبارسنجی، تأیید صریح و راهنمای فیلدها.
- planning/services.py: تراکنش تغییر، کنترل revision و idempotency.
- planning/views.py: هماهنگی فرم‌ها، query مجاز و پاسخ.
- templates و static: رابط فارسی RTL، فونت محلی و JavaScript تاریخ/راهنما.
- private: داده اجرا و تصویر آزمون؛ خارج از Git.

## قرارداد مسیرها

| مسیر | روش | ورودی و خروجی |
|---|---|---|
| /welcome/ | GET/POST | ورود صریح به هویت نمونه با CSRF؛ فقط loopback |
| /logout/ | POST | پایان نشست با CSRF |
| /، /programs/، /decisions/ | GET | q، status، sort، page؛ HTML فهرست مجاز |
| /programs/new/ | GET/POST | فرم برنامه با request_id و تأیید؛ redirect به جزئیات |
| /programs/{id}/ | GET | HTML برنامه متعلق به کاربر |
| /programs/{id}/edit/ | GET/POST | فرم و revision؛ تعارض 409، خرابی ذخیره 503 |
| /programs/{id}/followup/ | GET/POST | نتیجه، اقدام بعدی، موعد، revision و request_id |
| /versions/ | GET | نمایش تاریخچه نگارش‌های ثبت‌شده |

REST API عمومی وجود ندارد؛ این قرارداد فرم HTML نسخه نمونه است. تاریخ فرم YYYY-MM-DD، timestampها timezone-aware و نمایش شمسی با Intl در مرورگر است. ورود تاریخ فعلاً میلادی است.

## قواعد و محدودیت‌ها

- پیش‌نویس می‌تواند مسئول/موعد نداشته باشد؛ سایر وضعیت‌ها مسئول، اقدام و موعد می‌خواهند. انتظار پیش‌نیاز شرح مانع هم می‌خواهد.
- موعد اولیه حفظ می‌شود. تغییر و audit در یک تراکنش‌اند. revision قدیمی رد و ورودی فرم حفظ می‌شود.
- request_id تکراری با payload یکسان نتیجه قبلی را برمی‌گرداند؛ payload متفاوت تعارض می‌دهد. خطای نوشتن هم‌زمان دیتابیس ممکن است 503 بدهد؛ retry با همان فرم امن است.
- معیارهای تحلیلی نهایی، مدیریت مستقل اقدام/مانع، پیش‌نیازهای چک‌لیستی، لغو/تعویق، خاتمه برنامه و تأیید نتیجه کیس هنوز پیاده نشده‌اند. کارت‌ها فقط شمارش وضعیت جاری‌اند.
- کیس‌های موجود ساختگی و فقط‌خواندنی‌اند؛ برنامه جدید کیس خودکار نمی‌گیرد. ثبت پیگیری نتیجه کیس را تغییر نمی‌دهد.
- مسئول در نمونه متن آزاد است؛ هنوز نگاشت کاربر/تیم و مجوز قابل پیکربندی ندارد.
- CRM، تلفن، AI و worker وجود ندارند؛ timeout/cancel سرویس خارجی قابل آزمون نیست.
- داده واقعی وارد نشود. رمز سازمانی وجود ندارد؛ secret راه‌انداز موقت و محیطی است. restart نشست را نامعتبر می‌کند.
- کمک زمینه‌ای برای بخش‌ها و فیلدهای اصلی وجود دارد؛ پوشش تک‌تک عناصر و آزمون کامل WCAG/ASVS هنوز نهایی نیست.
- فرم‌ها ساده نگه داشته شده‌اند؛ بخش‌بندی فرم طولانی و انتخابگر شمسی در ادامه بررسی می‌شود.

## آزمون‌های انجام‌شده

۱۷ تست Django روی SQLite: ثبت تکراری و payload متفاوت، revision قدیمی، حفظ موعد مبنا، پیگیری بدون تغییر نتیجه کیس، جلوگیری از دسترسی کاربر دیگر، رد IP شبکه، لزوم ورود و CSRF، اعتبارسنجی، حذف برنامه آینده از کارهای امروز، rendering و escape متن، حفظ فرم هنگام خطای DB، rollback خطای audit، تأیید صریح و حفظ داده در seed مجدد.

بررسی نحوی JavaScript، system check Django و ایجاد migration انجام شد. در مرورگر واقعی ایجاد برنامه و ثبت پیگیری، نمایش نتیجه و تاریخچه، نمایش دسکتاپ و موبایل، بارگذاری فونت محلی و بستن راهنما با Escape همراه بازگشت focus بررسی شد. در عرض موبایل بررسی‌شده، عرض document از viewport تجاوز نکرد؛ جدول اسکرول داخلی دارد.

آزمون screen reader، انطباق کامل WCAG/ASVS، PostgreSQL، بار هم‌زمان واقعی، بازیابی بکاپ و اتصال CRM انجام نشده‌اند. مرورگر UI build جداگانه ندارد؛ templates و static مستقیم سرو می‌شوند.

برای تکرار تست‌ها:

```powershell
$env:SERVICE_SECRET_KEY = [guid]::NewGuid().ToString() + [guid]::NewGuid().ToString()
.venv\Scripts\python.exe manage.py test
.venv\Scripts\python.exe manage.py check
.venv\Scripts\python.exe manage.py makemigrations --check --dry-run

```
