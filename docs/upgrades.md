# داشبورد ارتقا و تازه‌سازی ردیف — 0.6.4

**اصلاح محدوده به درخواست کاربر:** استفاده از Done Version و محاسبه تعداد قابل رفع فعلاً متوقف است. پیاده‌سازی جاری فقط نگارش فعلی Account، مشتریان منطبق با معیار ذخیره‌شده منتخب و تعداد کیس‌های مرتبط را نمایش می‌دهد. کارت‌های آماری، نمودار مراکز با بیشترین کیس مرتبط و توزیع نگارش فعلی اضافه شده‌اند. تعداد مرتبط، پیش‌بینی رفع نیست. توضیحات مقایسه مقصد در دو بند بعد، طرح قبلی و فعلاً غیرفعال‌اند.

مقصد: /planning/upgrades/. منبع نگارش فعلی Automation Version در Account (brd_automationversion) و نگارش رفع تأییدشده توسط کاربر Done Version در Case (brd_doneversion) است. رابطه Account با outer join به View انتخابی کیس افزوده می‌شود؛ فیلترها و دامنه کیس‌ها حفظ می‌شوند. انتخاب مشتری از brd_account و سپس customerid مطابق نگاشت موجود است. نبود Account یا نسخه قابل مقایسه نتیجه نامشخص دارد.

هدف این نگارش شمارش رفع‌های ثبت‌شده دقیقاً در مقصد انتخابی است. تجمیعی‌بودن اصلاحات بین نسخه‌ها یا آمادگی عملیاتی نصب فرض نمی‌شود. عدد به معنی بسته‌شدن قطعی کیس نیست. فقط موارد منطبق با معیار ذخیره‌شده کاربر شمرده می‌شوند؛ حداقل گروه، فعال‌بودن، شرط، اولویت و دامنه جاری در معیارهای برنامه‌ریزی قابل ویرایش‌اند. مقصد از نسخه‌های واقعی Done Version انتخاب می‌شود. مشتری دارای نگارش‌های متناقض تا دریافت هماهنگ نامشخص می‌ماند.

کنار ردیف کیس و پروژه دکمه دریافت همان مورد قرار دارد. POST با CSRF، مجوز اپراتور و دامنه snapshot جاری کنترل می‌شود. کار در همان صف پس‌زمینه انحصاری CRM اجرا می‌شود؛ در صورت وجود دریافت جاری، درخواست جدید رد می‌شود. دریافت همچنان از View اصلی و Viewهای شواهد انتخابی است؛ خارج‌شدن مورد از View پیام خطا دارد و حذف یا فرض بسته‌شدن انجام نمی‌شود. انتشار پس از موفقیت همه شواهد اتمی است؛ لغو، خطا و تغییر منبع داده قبلی را حفظ می‌کند. اقدام‌های محلی تغییر نمی‌کنند.

آیکن ساعت کنار ردیف زمان آخرین دریافت موفق همان مورد را با ماوس یا فوکوس نمایش می‌دهد. دریافت ردیفی زمان آخرین دریافت کامل View را جلو نمی‌برد. رکورد پروژه زمان مستقل در JSON دارد؛ کیس زمان fetched_at و شناسه انتخاب منبع در evidence دارد تا دریافت ردیفی در همان View، snapshot جاری را نامعتبر نکند. دریافت از View دیگر همچنان snapshot ناسازگار را نامعتبر می‌کند.

نگارش 0.6.6: پالت هشت‌رنگ میله‌ها برای حالت روشن و تاریک اضافه شد. بخش مشتریان تازه ارتقایافته فعلاً وضعیت فقدان تاریخ معتبر را نشان می‌دهد؛ منبع تاریخ ارتقا هنوز مشخص نشده است و آمار ساختگی یا صفر فرضی نمایش داده نمی‌شود.

۰.۶.۸: آیکن ساعت کنار ردیف با کلیک، زمان آخرین دریافت موفق و پوشش یادداشت‌ها را نمایش می‌دهد. بازخوانی ردیف همه صفحات View یادداشت مرتبط را دریافت می‌کند؛ نبود View یادداشت صریحاً در نتیجه اعلام می‌شود. این پوشش تضمین همه یادداشت‌های خارج از فیلتر یا دسترسی CRM نیست.


۰.۶.۱۸: معیارهای نامرتبط از انتخاب ارتقا حذف شدند؛ کاربرد داشبورد هر معیار قابل تغییر است. راهنمای تعداد مرتبط مثال روشن دارد. شمارش قابل رفع همچنان غیرفعال است؛ Done/Goal Version یا زمان Release مدرک حل قطعی مشتری محسوب نمی‌شود.
