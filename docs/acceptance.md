# ماتریس پذیرش

تمام موارد زیر «اجرا نشده» هستند؛ این فایل برنامه آزمون است، نه گواهی انطباق.
مرجع کامل و بدون خلاصه‌سازی: [الزامات کاربر](user-requirements.md).

| حوزه | روش بررسی مورد نیاز | شاهد مورد انتظار |
|---|---|---|
| فارسی، RTL و فونت | بررسی DOM، درخواست شبکه، دسکتاپ/تبلت/موبایل | lang=fa-IR، dir=rtl، فونت محلی و نبود وابستگی CDN |
| حالت‌های UI و فرم | بدون داده، خطا، loading، تأیید، مجوز و حفظ ورودی | آزمون UI و بازبینی فارسی |
| دسترس‌پذیری | آزمون خودکار به همراه صفحه‌کلید، focus، screen reader و کنتراست | نگاشت الزامات WCAG 2.2 AA و نتایج دستی؛ ابزار خودکار به‌تنهایی کافی نیست |
| امنیت | مجوز endpoint/object، CSRF، XSS، تزریق، SSRF و مسیر فایل | نگاشت کنترل‌های قابل اعمال ASVS 5.0 و دلیل موارد غیرقابل اعمال |
| اسرار و اطلاعات | بررسی فایل، log، API، frontend و پشتیبان | عدم افشای secret و داده واقعی در مخزن |
| راهنمای زمینه‌ای | تطبیق تک‌تک اجزا با راهنما و منطق | کمک یکتا، بدون بریدگی، قابل استفاده با لمس و صفحه‌کلید |
| قرارداد داده | مستند API، مدل و migration | نسخه قرارداد، نمونه ساختگی و آزمون migration |
| هم‌زمانی و دسترسی | کاربران هم‌زمان روی PostgreSQL واقعی | تست conflict، scope و تراکنش audit |
| پردازش و یکپارچگی | retry، timeout، cancel، قطع شبکه و خرابی DB | job پایدار، عدم تکرار و حفظ cursor صحیح |
| کارایی | pagination/filter/sort/search با حجم نماینده | اندازه داده و زمان اندازه‌گیری‌شده؛ cache جداشده بر مبنای مجوز |
| انتشار و استقرار | راه‌اندازی تمیز، migration و restore | دستور اجرا، نمونه env بدون secret و گزارش بازیابی |
| نسخه و تاریخچه | نمایش نسخه و تاریخچه داخل برنامه | تاریخچه افزایشی با timestamp و بخش‌های تغییرکرده |

برای هر قابلیت باید هدف، ورودی، خروجی، قواعد، خطاها، فرض‌ها، راهنما و تست مرتبط در مشخصات همان قابلیت وجود داشته باشد. بررسی نحوی و build فقط پس از وجود کد قابل اجرا گزارش می‌شوند.
