# ServiceManagementApp

دستیار مدیریتی خدمات پس از فروش برای برنامه‌ریزی، پیگیری و بهبود کیفیت کار.

این پروژه مستقل از MyBarid-AI طراحی می‌شود. پروژه قبلی صرفاً مرجع تجربه و کدهای قابل بررسی برای استفاده مجدد است.

## وضعیت

نسخه محلی `0.3.0` آماده است: صفحه زیرسیستم‌ها، داشبورد مدیریت پروژه‌ها با گزارش‌های یادداشت، ماژول برنامه‌ریزی مبتنی بر Viewهای CRM، اقدام‌های مرتبط با کیس، تنظیمات عمومی/اختصاصی، رابط واکنش‌گرا، حالت تاریک و نمودارهای داشبورد. راهنما: [برنامه‌ریزی مبتنی بر CRM](docs/crm-planning.md) ، [مدیریت پروژه‌ها](docs/projects.md) و [رابط ماژولار](docs/modules-ui.md). نمونه ساختگی قبلی جدا و محفوظ است.

## اجرای نمونه روی ویندوز

نیازمند Python 3.14 (محیط بررسی‌شده) است. در پوشه پروژه:

```powershell
python -m venv .venv
python -m pip --python .venv\Scripts\python.exe install -r requirements.txt
.venv\Scripts\python.exe run_preview.py
```

اگر ساخت venv در مرحله ensurepip خطا داد ولی فایل Python محیط ساخته شد، دستور pip بالا وابستگی‌ها را مستقیماً در همان محیط نصب می‌کند.

پس از نصب، برای اجراهای بعد `./start-preview.ps1` نیز قابل استفاده است. آدرس: http://127.0.0.1:8765 . برای پورت دیگر: `.venv\Scripts\python.exe run_preview.py 8766` . برای توقف Ctrl+C بزنید.

راه‌انداز migration و ایجاد یک‌باره داده نمونه را اجرا می‌کند؛ داده‌های قبلی را بازنشانی نمی‌کند. کلید موقت را فقط در محیط فرایند تولید می‌کند؛ با راه‌اندازی مجدد باید دوباره وارد نمونه شوید، اما داده‌ها باقی می‌مانند. فایل داده در `private/preview.sqlite3` است و در Git قرار نمی‌گیرد.

این نسخه فقط روی loopback اجرا می‌شود و اتصال CRM با هویت ویندوز اجراکننده انجام می‌شود. آن را با تغییر bind، حذف کنترل IP یا reverse proxy در شبکه منتشر نکنید. ورود محلی احراز هویت سازمانی نیست. پایگاه داده PostgreSQL، نقش‌های تیمی و استقرار امن در فاز بعد ساخته می‌شوند.

## مسیر پیشنهادی تجربه

۱. ورود → صفحه اصلی زیرسیستم‌ها → برنامه‌ریزی.
۲. تنظیمات عمومی اتصال CRM → دریافت فهرست Viewها → انتخاب View در تنظیمات برنامه‌ریزی.
۳. بازخوانی → مشاهده نمودارها و کیس‌ها → ثبت اقدام محلی با مسئول و موعد.
۴. تغییر حالت روشن/تاریک از بالای صفحه و بررسی نمایش در اندازه‌های مختلف.

جزئیات پیاده‌سازی و محدودیت‌ها: [نسخه محلی](docs/preview.md).

## مبنای نسخه اول

- ۳ تا ۴ کاربر اولیه؛ استفاده داخل شبکه شرکت.
- نقش‌های مدیر خدمات، سرپرست و کارشناس.
- برنامه تحت وب، ماژولار و با پایگاه داده مرکزی.
- هدف: بهبود کیفیت و کمک به تصمیم‌گیری؛ بدون رتبه‌بندی خودکار کارکنان.
- اولین مسیر عملیاتی پیشنهادی: دریافت کیس از CRM، تعیین اقدام بعدی و مسئول و موعد، پیگیری و ثبت نتیجه.

جزئیات در [سند طراحی نسخه اول](docs/design-v1.md) ثبت شده است.

این مخزن عمومی است. اطلاعات واقعی مشتریان و کارکنان، خروجی CRM، رمز، توکن، فایل تنظیمات محرمانه و پشتیبان پایگاه داده نباید وارد Git شوند. نمونه‌ها باید ساختگی باشند. قواعد gitignore جایگزین بررسی محتویات پیش از انتشار نیستند.
